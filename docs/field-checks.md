## まだ確かめていないこと

| 何を | どうすれば確かめられるか |
|---|---|
| GitHub 上の指令リポジトリを、2 台の PC・別々のアカウントで読み書きする | 2 台で `install.ps1` → 同じタスクを両方から `claim` し、片方が終了コード 2 になること |
| `preflight.ps1` の GitLab の認証切れ・削除予定の検出（正常な場合は確かめた） | トークンが失効した状態で `NG 認証` と直し方が出ること。削除予定のプロジェクトで `NG push 先` が出ること |
| `preflight.ps1` の、指定のアカウントがログイン済みだが有効でないときの案内（`gh auth switch`） | `gh` に 2 つのアカウントでログインした PC で、有効でないほうを `project.md` に書いて実行する |
| 上限 → `auto-resume-global` の再開 → `/auto-loop resume` の一連 | `install.ps1 -LinkAutoResume` のあと、実際に上限で止まったとき。`~/.claude/auto-resume-global/logs/auto-resume.log` の再開の行と、タスクファイルのログの「再開:」の行の時刻を照らす |
| 分岐後の「仕上げ」の委任（止まったサブエージェントの作業ツリーを引き継ぐ） | 委任の実行中に中断が起きたとき。タスクファイルの「委任」の表が「停止 → 仕上げ中 → 完了」と進むこと |
| Claude Code 以外のエージェント（Copilot など）が `AGENTS.md` の手順で担当を主張する | 実際に 1 件通す |
| 利用者が GitHub の画面でタスクファイルに回答を書き、エージェントが次の同期で読む | `waiting` のタスクで試す。同じ箇所を同時に書いたときの競合の直し方も確かめる |
| macOS / Linux の `pwsh` での動作 | `tests/smoke.ps1` を流す |
| 自動起動（`AutoLoopKick`）: 実際のログオン・スリープ復帰のあとに `kick.ps1` が動き、新しいウィンドウでセッションが起きて `/auto-loop next` を実行する（間隔の起動では確かめた。ログオン・スリープ復帰の契機はまだ） | `install.ps1 -EnableKick` のあと、ログオン・スリープ復帰をまたぐ。`logs/auto-loop.log` の `[kick]` の行（起こした・見送りの理由）と、タスクファイルのログの `next:` の行を照らす |
| 自動起動: `AutoLoopKickWeekly`（週の解除時刻の 6 分後）が、その時刻に PC を起こして動く（登録と、間隔の起動は確かめた） | 次の週の解除時刻（A-MSI では 11/26 08:06）のあとに、`logs/auto-loop.log` の `起動のきっかけ: weekly` の行。スリープ中なら、電源のスリープ解除タイマーが有効か |
| 自動起動: 権限の確認待ちや、15 分を超えるツールの実行を、止まっているとみなしてしまわないか（入力待ちを数えないこと・手を動かしているセッションで見送ることは確かめた） | 長い試験を流している間に `kick.ps1 -DryRun` して、`SKIP ほかのセッションが動いている` になるかを見る。権限の確認で止まったまま 15 分を過ぎたときの判断（`stale`）も見る |
| 自動起動: 記録が書かれなくなったセッションを終わらせる見張り（`idleCloseMinutes`）。別のプロセスに替えたあと、本番で働くか（スレッドのときは働かなかった）。長い処理（試験など）の途中で終わらせてしまわないか | 起こされたセッションを放置し、`[close-watch] 閉じた: … idle-close` の行と、そのときの作業の状態を確かめる。`[close-watch] 見張りを始めた` の行が無ければ、見張りが起動していない |
| 判断待ち・完了で終わらせる見張り（`settledCloseMinutes`）を本番で: 実際のタスクを `waiting` / `done` にしたセッションが 5 分後に閉じる。判断待ちにしたあと別のタスクを続けているセッションは閉じない。サブエージェントが動いている間は閉じない | 自動起動を有効にした PC で、`logs/auto-loop.log` の `[close-watch]` の行（始めた・見送り・閉じた）と、タスクファイルのログの時刻を照らす |
| 自動再開したセッションの見張り: 本番の上限からの再開のあと、`kick.ps1` が見張りを付け、判断待ち・完了で閉じる。`auto-loop` 以外の作業の再開は閉じない | 上限からの再開のあとの `[kick] 再開したセッション … 見張りを付けた` と `[close-watch]` の行 |
| 自動起動: 上限の解除待ちのとき（復帰タスクが登録されている）に見送る | 上限で止まった状態で `kick.ps1 -DryRun` を実行し、`SKIP 上限の解除待ち` が出ること |
| 自動起動: 復帰タスクが無いまま上限で止まっているとき（手でスリープ解除した・対象外のセッション）に、セッションの記録から見送る | 上限で止まった状態で復帰タスクを無効にし（または `auto-resume-global` の対象外のフォルダで止め）、`kick.ps1 -DryRun` で `SKIP 上限の解除待ち（セッションの記録: …` が出ること。解除のあと、普通の応答が書かれたら見送らなくなること |
| 手が空いたときの作業を 1 件、定義から起票して行い、`最終実施:` が書き換わる | 通常のタスクが無い状態で `/auto-loop next` を実行する |
| スキルの説明文での自動適用（「ループの状態を見せて」などで起動するか） | 導入後の会話で確かめる |

## 記録の足し方

- 「いつ・何が起き・何で確かめたか（ログの行・コマンド・画面）」を 1 行で
- 期待と違ったら、「確かめたこと」に事実を書き、直したなら何を直したかを添える。原因が断定できないときは「推測」と書く
